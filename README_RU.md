# FrameAutoSize R1.4 — размеры рамы на двух видах

**Статус: первый кандидат. Проверен статически; в SolidWorks не запускался.**
Первое действие после импорта — `Debug → Compile`, затем диагностические запуски на двух видах.

## Изменение R1.4 — контекст приложения

Пользователь получил `ActiveDoc = Nothing` при запуске на выбранном чертеже. Прежний журнал фиксировал только общий отказ, поэтому точная причина не установлена. Скриншот пустого шаблона VBA не доказывает неверный выбор процедуры.

В R1.4 ссылка на активный документ запоминается до открытия журнала; журнал использует тот же объект приложения. При каждом запуске добавляются PID экземпляра SolidWorks, число и список его открытых документов, активный документ до/после открытия журнала, типы документов и сведения о выделении. Добавлена команда `DiagnoseContext`, которая выполняет только эту диагностику и завершает работу до геометрии/создания размеров. Другие экземпляры приложения не подключаются, документы не активируются и не сохраняются.

Для проверки текущего отказа после импорта R1.4 выполните `Debug → Compile`, затем **только `FrameAutoSize.DiagnoseContext`** обычным для вас способом, сохранив выбранный чертёж. Пришлите TXT рядом с SWP. Если запуск без активного документа повторится, в журнале теперь будет контекст, а не только «Откройте чертёж».

Правила размеров R1.3 сохранены. Проверены грамматика и доступность 85 методов/свойств и 11 констант interop; нативный запуск R1.4 не проверен. Причина потери активного документа пока не объявляется исправленной.

## Изменение R1.3

Нативная диагностика R1.2 спереди прошла: найдены 19 тел профилей, корректная база, семь размеров 156,5 / 182 / 480 / 600 / 901 / 1265 / 1410 мм; все 14 выборов базовых и целевых рёбер успешны. Это подтверждение чтения геометрии и выбора рёбер, не создания размеров.

Диагностика сверху остановилась на проверке места для размерных линий. Уголки ошибочно участвовали в габарите; торцы стоек не участвовали в целях. По исходному скриншоту и подтверждению пользователя 17.11.2026 переработаны правила верхнего вида: только трубы/швеллеры, торцы стоек, пропуск координат примыканий наружной рамы. Новый набор по координатам из журнала: X 355/600/640/1220, Y 235/350/370. При недостатке места у края линии переносятся на другую сторону. Правила вида спереди сохранены.

Статическая проверка грамматики прошла. Выражения отбора из исходника проверены на габаритах 19 тел из пользовательского журнала; получен согласованный набор, якоря помещаются на листе 420×297. Создание и визуальное оформление размеров R1.3 в SolidWorks ещё не проверены. Архивы R1, R1.1 и R1.2 сохранены.

## Изменение R1.2

В двух пользовательских журналах R1.1 преобразованные единичные точки Y и Z совпадали с началом координат. Из-за вырожденного преобразования в `GetExtremePoint` передавалось нулевое направление. Ошибка возникала до распознавания профилей и создания размеров.

`Project` теперь передаёт в `MathUtility.CreatePoint` явный массив `Double(0 To 2)`, как требует контракт API, вместо массива вариантов от VBA `Array()`. До преобразования проверяются координаты созданного `MathPoint`. После преобразования проверяются длины и взаимная перпендикулярность трёх осей, а направление поиска экстремума нормализуется. При ошибке записываются направление и этап. Свойства LENGTH дополнены статусами чтения в журнале.

Первая повторная проверка: заменить модуль на R1.2, выполнить `Debug → Compile`, затем `DiagnoseFront` и `DiagnoseTop`. Нативное устранение сбоя ещё не подтверждено. Журналы сохраняются рядом с SWP, как в R1.1. Файлы пользовательских журналов в репозиторий не добавляются.

Проверки: выражения новой проверки осей отвергают оба вырожденных преобразования из журналов, принимают 36 корректных масштабированных/повёрнутых/зеркальных вариантов; ещё два некорректных варианта отвергнуты. 240 численных проверок выражений экстремумов повторно пройдены. Это не выполнение VBA или SolidWorks.

Контракт API: https://help.solidworks.com/2025/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IMathUtility~CreatePoint.html — вход `ArrayDataIn`: массив double с координатами точки.

## Установка

1. Распакуйте архив в обычную папку Windows.
2. В SolidWorks создайте новый VBA-макрос: **Сервис → Макрос → Создать**, сохраните как `FrameAutoSize.swp`.
3. В редакторе VBA импортируйте `FrameAutoSize.bas`: **File → Import File**. Пустой автоматически созданный модуль нового макроса можно удалить. Соседние модули существующих макросов не трогайте.
4. В **Tools → References** должны быть включены библиотеки SolidWorks и SolidWorks Constants установленной версии.
5. Выполните **Debug → Compile VBAProject** и сохраните макрос.

BAS поставляется в CP1251 с CRLF и `Attribute VB_Name`, для импорта. `FrameAutoSize.txt` — тот же исходник без Attribute в UTF-8, для копирования в редактор. Не импортируйте оба файла. Готовый SWP здесь не создавался: его необходимо сохранить в редакторе SolidWorks.

## Первый запуск: диагностика

1. Откройте копию чертежа со связанными моделями. Сборка и деталь рамы должны быть полностью загружены.
2. Выберите **один вид спереди**, запустите `FrameAutoSize.DiagnoseFront`.
3. В сообщении будет полный путь к журналу `FrameAutoSize_....txt` рядом с файлом `.swp`. Скопируйте журнал.
4. Выберите **вид сверху**, запустите `FrameAutoSize.DiagnoseTop`, скопируйте второй журнал.
5. Пришлите оба TXT. Если ошибка возникла на Compile — вместо журнала нужны текст ошибки и выделенная строка.

Диагностика читает геометрию и свойства списка вырезов, составляет план, проверяет сопоставление и выбор рёбер. Размеры не создаёт, документы не сохраняет, режим размеров и настройки ввода не меняет. Проверка рёбер меняет текущее выделение.

`Diagnose` пытается определить режим по стандартному имени ориентации; если имя не сообщает Front/Top, журнал содержит геометрию без плана. Для первой проверки используйте именно `DiagnoseFront` и `DiagnoseTop`.

## Простановка размеров

- Выделите вид спереди → `FrameAutoSize.Front`.
- Выделите вид сверху → `FrameAutoSize.Top`.
- Либо используйте `FrameAutoSize.main`: Front/Top определяется по стандартному имени ориентации. Для проекционного/именованного вида, где SolidWorks не сообщает это имя, появляется выбор «спереди / сверху».

Назначьте `Front` и `Top` двум кнопкам SolidWorks, если нужен запуск без выбора режима. Макрос работает только на выбранном существующем виде. Повторный запуск добавляет размеры повторно. Учёта ручных размеров и удаления прежних размеров нет.

## Правила R1

### Рама в сборке

Автоматически ищется одна деталь, в имени файла которой есть `рама` или `frame`. Это выделяет `рама.sldprt` среди добавленных ножек, уголков, пластин и крепежа. Если имя другое, измените `FRAME_NAME` в начале модуля. При нескольких совпадениях макрос останавливается и перечисляет компоненты в журнале. Для отдельного вида детали используется сама деталь.

Обмеряются видимые в исходной детали твёрдые тела распознанных профилей рамы. Прочие компоненты сборки не обходятся для размеров. Внутри рамы трубы, швеллеры и уголки распознаются по именам/свойствам списка вырезов или происхождению от `WeldMemberFeat`; тела с признаками листа/пластины исключаются. Неопознанные тела записываются в журнал как `profile=False` — их список обязательно проверить на первом запуске.

Ось профиля устанавливается по параллельным прямым рёбрам, соответствующим связанному и разрешённому свойству `LENGTH`. Единицы десятичной длины берутся из детали: мм/см/м/дюймы/футы. Не используется правило «самое длинное ребро». Короткие уголки и трубы допустимы, если LENGTH однозначно подтверждает ось. При отсутствии подтверждённой оси распознанного профиля простановка останавливается; диагностика сохраняет сведения о нём.

### Спереди

- Нижний опорный профиль определяется среди профилей с горизонтальной продольной осью по самому низкому нижнему уровню. Если на этом уровне несколько профилей, у них должна быть общая верхняя отметка; привязка берётся к самому длинному из них.
- База всех высот — **верхняя наружная кромка этого опорного профиля**.
- Цели — **верхние наружные кромки** профилей, ось которых горизонтальна на виде или направлена к наблюдателю/от него. В частности, для трубы 50×50 размер 480 должен идти к её верхней поверхности, а не к оси и не к низу.
- Вертикальные стойки не образмеряются. Цели на уровне базы и ниже пропускаются.
- Совпадающие высоты объединяются. Размерные линии распределяются слева/справа по расположению целевого профиля; малые расстояния ближе к контуру.

### Сверху

- Общая база — левый нижний угол габарита труб и швеллеров самой рамы. Уголки сверху исключаются и из целей, и из габарита; их выступы не смещают базу и размерные линии.
- У профилей с продольной осью вдоль вертикали листа создаются размеры X от левой базы.
- Торцы вертикальных стоек (ось в глубину вида сверху, на листе виден квадрат сечения) участвуют в размерах X и Y.
- Для X целевая кромка — левая, для Y — нижняя. Все размеры идут от одной общей базы.
- Макрос находит внутренние границы наружных профилей рамы. Если стойка/поперечина примыкает к левому или правому наружному профилю, её X не добавляется; если торец стойки примыкает к нижнему или верхнему наружному профилю, его Y не добавляется. Координата примыкания определяется по габариту тела относительно внутренней границы наружного профиля. Так исключаются избыточные размеры сечения и примыканий наружной рамы.
- Профили, лежащие горизонтально на листе, используются для определения наружного контура, но отдельные Y до них не добавляются. Положение внутренних узлов показывается по торцам стоек.
- Одинаковые координаты объединяются. Размеры X располагаются снизу, Y — справа. Если места у края листа не хватает, используются верхняя/левая стороны.
- Дополнительно создаётся общая ширина рамы сверху. Для отключения установите `TOP_OVERALL_WIDTH = False`.

Согласованный с пользователем набор на исходном примере: **X: 355, 600, 640, 1220; Y: 235, 350, 370 мм**. Это ожидаемые результаты для примера, не числовые константы макроса: все координаты вычисляются по геометрии.

## Проверка и ограничения

Размеры создаются штатными `AddHorizontalDimension2`/`AddVerticalDimension2`, с ассоциативными привязками к реальным рёбрам экземпляра рамы. Геометрия проходит преобразования экземпляра и вида; численное значение проверяется в метрах модели сразу и после перестроения. Текстовых подстановок значений нет.

Для выбранного вида при простановке включается проекционный режим размеров. При успехе он остаётся включённым; при ошибке восстанавливается прежний. Настройка запроса значения размера временно отключается и восстанавливается. При отказе макрос пытается удалить только размеры текущего запуска. Сохранение файлов не выполняется.

Пока поддерживаются полные ортогональные виды без разрывов, обрезки, местных/обычных разрезов и фильтра отдельных тел. Изометрия, косые профили, изменённая сборочными операциями геометрия, круглые трубы без подходящих прямых кромок и произвольные способы построения профилей не проверены. Активные конфигурации сборки и детали должны совпадать с конфигурациями вида и экземпляра; макрос их не переключает.

Скрытые в исходной детали тела исключены. Полностью перекрытые другими компонентами профили исходной рамы могут участвовать: для них используется исходная геометрия, а не только видимые рёбра. Индивидуальное скрытие тел/специальные состояния отображения внутри сборочного вида требуют отдельной проверки в SolidWorks.

Если на основной стороне не хватает места для якорей размерных надписей, используются противоположные стороны. Если и там места недостаточно, план останавливается до создания размеров. Полной проверки пересечений текста с геометрией, рамкой, штампом и соседним видом пока нет; размеры используют фиксированные отступы 7 мм и шаг 6 мм на бумаге.

Для первого нативного приёмочного теста проверьте:

- найдена именно `рама.sldprt`, прочие компоненты исключены;
- среди `profile=False` нет нужных труб/уголков;
- база спереди — верх опорного швеллера, размер 480 — верх трубы 50×50;
- у уголка с высотой 901 определилась ось к наблюдателю, стойки не получили высот;
- сверху верны левая/нижняя базы и выбор ближайших к ним кромок;
- размеры остаются привязанными после переноса поперечины и перестроения.
