# FrameDrawingPackage P1.1 — один чертёж, по три листа на раму

Первый интеграционный кандидат для SolidWorks 2025. Исходники проверены статически; создание всего комплекта в SolidWorks ещё не испытано. Самостоятельный FrameAutoSize в корне репозитория не заменяется.

## Что делает

Запуск из сохранённой сборки создаёт **один новый документ чертежа**. Для каждой найденной рамы создаётся отдельная тройка листов:

| Лист | Модель | Обработка |
|---|---|---|
| Общий | Сборка в выбранной конфигурации, изометрия | Длины тел выбранной детали рамы: FrameCutListDimensionsV3 |
| Сверловка | Именно деталь выбранной рамы и её конфигурация | InsertWeldWithHoles: отбор тел с отверстиями, виды, размеры, позиции, список вырезов |
| Монтаж | Сборка в выбранной конфигурации, спереди и сверху | FrameAutoSize: монтажные размеры только выбранной рамы |

Для четырёх рам получается один чертёж с 12 листами. Имена начинаются с F001/F002 и содержат короткое имя детали рамы. Одна и та же рама в разных выбранных конфигурациях обрабатывается отдельно, поскольку конфигурации могут задавать разный состав сборки.

## Как выбирать несколько рам

Используются **конфигурации и реальные компоненты сборки**, а не поиск файлов в папке на диске.

- Если конфигурация одна, она обрабатывается сразу.
- Если конфигураций несколько, появится список: `0` — текущая, `*` — все, `1,3` — выбранные номера.
- В каждой выбранной конфигурации обрабатываются все видимые неподавленные детали с `рама`/`frame` в имени файла. Путь и конфигурация детали берутся из её экземпляра в сборке.
- Если в одной конфигурации видны четыре рамы, создаются четыре тройки листов. Размеры первой и третьей страниц каждой тройки относятся к конкретному экземпляру рамы; остальные детали не образмеряются.
- При этом **виды сборки показывают весь видимый состав этой конфигурации**. Для изолированного изображения каждой рамы с её аксессуарами подготовьте отдельную конфигурацию сборки на каждую раму, подавив/скрыв остальные группы. Автоматического разнесения произвольных уголков, ножек и пластин по рамам нет.
- Если детали рам названы иначе, измените `FRAME_TOKEN` в FrameDrawingPackage.

Снимок конфигураций деталей делается до обхода конфигураций сборки. После выполнения или ошибки выполняется восстановление исходных конфигураций. После восстановления проверяются значения и привязки созданных размеров.

## Установка в SWP

В приложенном пользователем `Авторазмер Рамы.swp` обнаружены только бизнес-модуль `FrameCutListDimensionsV3` и служебный `ThisLibrary`. Код встроенного модуля совпадает с предоставленным BAS без учёта регистра идентификаторов VBA. Форм или отдельного модуля создания чертежей в этом SWP не обнаружено.

1. Сделайте копию исходного SWP и откройте её редактором VBA в SolidWorks.
2. Удалите старый модуль `FrameCutListDimensionsV3`. Если в копии уже есть старые FrameAutoSize или InsertWeldWithHoles, замените и их. **ThisLibrary/SOLIDWORKS Objects не удаляйте.**
3. Импортируйте из этого комплекта все пять BAS:
   - `FrameDrawingPackage.bas`
   - `FramePackageSupport.bas`
   - `FrameCutListDimensionsV3.bas`
   - `InsertWeldWithHoles.bas`
   - `FrameAutoSize.bas`
4. В Tools → References должны быть включены библиотеки SolidWorks и SolidWorks Constants установленной версии. DLL/COM-регистрация не нужны.
5. Выполните **Debug → Compile VBAProject**, затем сохраните SWP под новым именем, например `Комплект рам.swp`.
6. В окне сборки запустите **FrameDrawingPackage.main**. Это единственная публичная команда без аргументов в комплекте.

BAS поставляются в CP1251/CRLF с Attribute для импорта. TXT — читаемые UTF-8 копии для просмотра кода. Не импортируйте BAS и TXT одновременно. Бинарный SWP не пересобирался: рабочий SWP необходимо сохранить редактором SolidWorks после импорта.

Это отдельная интеграционная версия модулей. Их RunForPackage получают приложение, документ, вид и экземпляр рамы от координатора. Не заменяйте ими модули самостоятельных рабочих SWP, если хотите сохранить их отдельные команды запуска.

## Шаблон и формат

- Используется стандартный шаблон чертежа SolidWorks из настройки `swDefaultTemplateDrawing`.
- Можно задать свой путь `.drwdot` в `DRAWING_TEMPLATE` в FrameDrawingPackage. Если настройка пуста и шаблон по умолчанию не найден, предлагается указать путь.
- Шаблон должен содержать **один исходный лист**, формат — A3 альбомный или больше. Новые листы получают размер, формат и параметры первого листа. Два монтажных вида размещаются в одном масштабе с резервом под размеры снизу/слева.
- Для сверловки сохранены правила масштаба, разрывов, размеров и позиций исходного InsertWeldWithHoles R35. Константа `TABLE_TEMPLATE` оставлена пустой: внутренние сетевые пути не публикуются. Для корпоративной таблицы укажите путь к своему `.sldwldtbt` локально в модуле InsertWeldWithHoles. Без него используется исходный поиск стандартного шаблона SolidWorks.
- Если сверловка не помещается в физический лист или часть видов/размеров не обработана, общий результат содержит предупреждение. Для большого числа деталей может потребоваться больший формат шаблона.

## Сообщения и сохранение

При полном выполнении всех трёх этапов для всех рам и отсутствии предупреждений — только **«выполнено успешно»**.

При частичном результате указываются этап/лист и пропуски. При опасном отказе последующие этапы останавливаются, уже созданный чертёж остаётся открытым для проверки. Это не атомарная транзакция всего чертежа; локальные откаты исходных модулей сохранены.

Чертёж **не сохраняется на диск автоматически**: проверьте его и сохраните штатной командой SolidWorks. Исходные сборка и детали также не сохраняются. Конфигурации временно переключаются, список вырезов обновляется исходным модулем сверловки. Автоматического удаления/замены старых чертежей нет.

Журналы и служебные файлы не создаются. Сведения о ходе работы доступны в Immediate редактора VBA (Ctrl+G).

## Ограничения и первая проверка

Детали рам должны быть сохранены и полностью загружены (Resolve). Виртуальные несохранённые детали, облегчённые/недоступные компоненты и произвольные названия без FRAME_TOKEN не считаются автоматически поддержанными. Для длин CutList сохранён исходный контракт LENGTH в миллиметрах.

Видимость сборочных видов определяется конфигурацией. Специальное индивидуальное скрытие компонентов в чертёжном виде и нестандартные состояния отображения требуют проверки. Геометрические ограничения исходных макросов (косые элементы, неоднозначные кромки, сборочные изменения геометрии) сохраняются.

Начните с одной конфигурации и одной рамы на копиях моделей:

1. Compile проходит без ошибки.
2. Созданы ровно три листа в одном новом чертеже.
3. На первом — сборка, длины относятся только к выбранной раме, истинный режим размеров.
4. На втором ссылка именно на нужный SLDPRT и конфигурацию; виды/размеры/позиции сверловки соответствуют исходному макросу.
5. На третьем — два вида сборки, монтажные размеры относятся к нужному экземпляру, сверху X снизу и Y слева.
6. После завершения восстановлены исходные конфигурации. После ручного сохранения/повторного открытия размеры не потеряли привязку.
7. Затем проверить две конфигурации/несколько рам: один документ и по три листа на каждое задание, без смешения деталей и конфигураций.

## Выполненные проверки

- VBA 7.1 grammar для пяти модулей.
- Контракты межмодульных вызовов, порядок трёх этапов, одна команда main, отсутствие операторов записи служебных файлов.
- Наличие и сигнатуры 60 методов/свойств нового координатора и поддержки, семь констант по interop SolidWorks.
- Совпадение исходника FrameCutListDimensions в SWP и отдельном BAS без учёта регистра.
- Упаковка BAS/TXT, кодировки, контрольные суммы.

Это статические проверки, не компиляция VBE и не исполнение COM. Нативного запуска P1.1 в SolidWorks не было. Исходные самостоятельные рабочие версии сохранены отдельно.

## Исправление P1.1

Все вызовы Require в FrameDrawingPackage и FramePackageSupport переведены в явный синтаксис Call Require(...). Это устраняет ошибку Syntax error на проверках Is Nothing. При обновлении P1 замените только эти два модуля; три рабочих модуля и локальный путь TABLE_TEMPLATE сохраняются. Выполните Debug → Compile перед запуском.
